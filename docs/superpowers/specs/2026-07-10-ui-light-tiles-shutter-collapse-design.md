# UI 再構成: 照明タイル + シャッター個別操作の折りたたみ 設計

日付: 2026-07-10
状態: 承認済み（モックアップで合意: `.superpowers/brainstorm/` の B+C 合体案）

## 背景 / 動機

現行 UI はライトカードもシャッターカードと同じ横長カード + 四角ボタンで、
「全部シャッターに見えて分かりづらい」（ユーザー）。また利用は基本一括操作のみで、
個別シャッターのカード列は普段ノイズになっている。

モックアップ 3 案（A: 暖色 + トグルスイッチ / B: 電球ボタン = スイッチ /
C: セクション分け + タイル）から **B + C の合体案**で合意。

## 決定事項（UI 構成）

1. **セクション分け。** ページを「💡 照明」「🪟 シャッター」の見出し付きセクションに分ける。
   照明が上、シャッターが下（モック合意どおり）。デバイスが存在しない kind の
   セクションは見出しごと出さない。

2. **ライトはタイル。** 2 列グリッドの正方形寄りタイル。
   - タイル中央の**大きな丸い電球ボタン（💡）がスイッチ**。押すと現在表示中の状態の
     反対を送る: 表示が `on` なら off、`off` / `unknown` なら on。
   - 点灯中はタイルをアンバー系（暖色）に色付け + 電球が光る。消灯/不明はグレースケール。
   - 状態ラベル（点灯/消灯/不明）はタイル内に小さく表示。
   - 表示状態は初回取得 + 操作後追いつき取得のみで古い可能性がある（壁スイッチ操作等）。
     トグルが外れても追いつき取得で表示が実態に戻るベストエフォートを受け入れる
     （`2026-07-10-light-async-state-design.md` の方針のまま。挙動・API は不変更）。

3. **プリセットは色玉スウォッチ。** タイル下部に丸い色玉を横並び。
   - config の `[[device.preset]]` に**任意フィールド `color`**（CSS color 文字列、
     例 `"#ffd9a0"`）を追加し、API の `presets[]` に `color` を含める。
   - `color` があれば色玉、なければ現行どおりテキストチップで表示（後方互換）。
   - 選択リング（縁取り）は「このセッションで最後に押したプリセット」にのみ付ける。
     サーバは現在色を知らないので「現在の色」を主張しない（原則 7: 嘘をつかない）。
     リロードでリングは消える。

4. **シャッターは一括カードが主役、個別は折りたたみ。**
   - 一括カード（開ける/閉める/止める + 開閉サマリ）は現行のまま。
   - カード下端に「**個別に操作 ▾ / ▴**」のテキストボタンを追加。押すとカード内に
     メンバーの行（デバイス名 + 状態ドット/ラベル + 開/閉/停 の小ボタン）が展開される。
   - 初期状態は折りたたみ。展開状態はクライアントのみ（保存しない、リロードで閉じる）。
   - 個別行の操作は現行 `deviceAct` と同じ（set 後同期確認、原則 7 維持）。
   - どのグループにも属さない shutter は、現行の横長カードのままシャッターセクション内に並べる。
   - 一括カードの `position: sticky` は廃止（照明セクションが上に来て
     追従がレイアウト崩れの原因になる。ページは 1 画面に収まる想定）。

5. **ポーリングは不変。** shutter は折りたたみ中も 4 秒ポーリング継続
   （サマリ「開 n / 閉 n」の鮮度のため）。light は初回 1 回 + 操作後追いつきのみ。
   `renderState` は行が非表示（折りたたみ中）でも DOM を更新するだけなので分岐不要。

## サーバ変更（追加のみ・小）

- `src/config.rs`: `Preset` に `pub color: Option<String>` を追加（`#[serde(default)]`）。
  値の形式検証はしない（CSS にそのまま渡す。信頼できるのは設置者自身の config のみ）。
- `src/main.rs`: `PresetInfo` に `color: Option<String>` を追加し `list_devices` で写す。
- API・エンドポイント・exec 経路はそれ以外一切不変。**変更の本体は `index.html` のみ。**

## index.html 実装ポイント

- `boot()`: devices を kind で二分し、照明セクション（タイルグリッド）→
  シャッターセクション（グループカード + 非所属カード）の順に構築。
- `buildLightCard` → `buildLightTile` に置き換え（電球ボタン + スウォッチ）。
  busy 制御・`lightAct` / `presetAct` / `scheduleLightCatchup` はそのまま使う。
  電球ボタンの送信 op は押下時点の `c.state` から決める。
- `buildGroup`: 展開ボタンと member 行コンテナを追加。member 行は
  `buildMemberRow(dev)` として生成し、`cards` マップには現行カードと同じ形
  （statusEl / labelEl / msgEl / buttons / kind / state）で登録する —
  `renderState` / `setDeviceBusy` / `updateGroupSummaries` を無改修で通すため。
- グループ member は config 検証で shutter 限定済み。member の行とは別に
  独立カードは作らない（同一デバイスの二重登録を避ける）。
- 一括操作中の全ボタン無効化（`setAllButtonsDisabled`）は展開行のボタンも対象
  （`cards` 経由で自然に含まれる）。
- 点灯タイルの配色はアンバー（`#ffb84d` 系）を新変数 `--lamp` として追加。
  既存の緑（open）/ 琥珀（closed）とは区別する。

## config.example.toml

- `[[device.preset]]` の例に `color = "#ffd9a0"` を追記し、
  「color を書くと UI が色玉で出す。省略時はテキストチップ」の注記を添える。

## テスト / 検証

- `cargo test`: `devices_list_has_kind_and_presets` に `color` の検証を追加
  （指定あり → 値が返る、なし → null）。既存テストは全通過。`cargo clippy -- -D warnings`。
- UI 実機（jarvis に `task deploy` 後スマホ/ブラウザ）:
  - 照明タイル: 電球押下で点/消がトグルし、~2 秒後に表示が追いつく。
    色玉押下で色が変わり、リングが移る。
  - シャッター: 折りたたみ初期表示 → 展開 → 個別操作 → 一括操作中は全ボタン無効。
  - light が 0 台 / shutter が 0 台の config でセクションが消えること（ローカル確認で可）。

## やらないこと

- light のグループ対応（config 制約のまま）。
- 展開状態の永続化（localStorage 等）。
- プリセットの「現在色」表示（サーバが知り得ないため）。
- shutter 操作の非同期化・API 変更。
